# 项目配置降级为构建输入，发布路径走运行时绑定

打包发布的应用不随包分发、也不在运行期读取 `maclauncher.json`：项目配置降级为 codegen 的构建输入——SDK 提供生成器把配置直译为应用代码引用的 Dart 常量（projectId、服务 id 与显示名），打包应用经握手自报建立运行时绑定（ADR 0003 的主路径）。配置绑定保留为开发期联调路径，不废除。

选择 codegen 而非「把配置拷进 app bundle 运行期读取」，是因为能力集由代码回调派生——运行期文件既无法增加能力（没有回调的服务不可操作）也无法安全删减（回调仍在代码里）；且未签名 DMG 内的文件可被手改、更新替换即漂移，运行期装载等于重新引入配置失效与身份漂移整套状态机。codegen 让开发期关联的配置与发布期握手自报同源，漂移在结构上不可能。

## 已确认的决策

- **JSON 是源、代码是产物、回调是能力真相**：生成常量被代码引用即对齐；服务 id 不一致在构建期暴露，绝不静默合并。
- **codegen 产物只含 projectId 与服务清单（id、显示名）**：entry 显式排除——打包后安装路径构建期不可知，由 `SdkEntry.currentAppBundle()` 运行期推断；JSON 的 `entry` 段仅服务开发期配置绑定。
- **SDK 运行期零变更**：握手协议、连接行为、绑定模型不动；旧版本 SDK 与既有绑定不受影响。任何向运行期加配置读取逻辑的提案默认违背本 ADR。
- **生成文件入库**：`maclauncher_manifest.g.dart` 提交进应用仓库、随代码评审；生成器只产常量，不产运行期断言样板（漂移由开发期握手一致性校验兜底）。
- **打包脚本属于各接入应用仓库**，不在本 ADR 范围；本仓库交付 SDK 生成器、example 示范与集成文档。
