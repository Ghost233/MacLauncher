# Launcher 以项目许可约束应用原有菜单栏入口

Launcher 模式允许用户按项目选择是否允许独立应用显示原有菜单栏入口。关闭许可时要求应用隐藏入口；开启许可时交由应用自身的显示设置决定，不能把许可开启当作入口已经可见。网速等动态内容与原有菜单仍由应用提供，项目关联和服务管理继续保持，以便 VPN 等项目保留自身展示能力，同时延续应用拥有生命周期与界面的职责边界。

## 已确认的产品行为

- 项目卡片提供“允许应用显示菜单栏”开关，按项目标识保存在 Launcher 本地，不写回项目配置；配置绑定与运行时绑定行为一致。已有和新关联项目均默认关闭。
- 关闭许可时，请求应用暂时隐藏入口；开启许可时，撤销 Launcher 的隐藏约束，由应用自身设置决定是否显示。Launcher 不改变应用自身的显示设置，不负责绘制网速或原菜单。
- 应用在线时立即请求应用，离线时允许修改并保存，提示等待连接；下次连接按已保存许可应用，无需重启应用。
- 请求拒绝或超时后保留用户选择，提示“尚未应用”并提供重试，下次连接再次应用。确认只代表应用接受显隐约束，不能据此断言应用入口可见。
- 在线应用未声明菜单栏控制能力时，开关置灰并显示“应用不支持菜单栏控制”；其余项目管理功能继续可用。
- 解除绑定时清除该项目的菜单栏许可，再次关联后默认关闭。项目改名、路径迁移或绑定来源变化，只要项目标识和原绑定保留，就保留许可。

## 实施边界与验证

沿用 ADR 0001 的职责边界：Launcher 保存许可并发送请求，应用负责实际菜单栏入口。现有 `setEntryManaged(true)` 用于隐藏，`setEntryManaged(false)` 用于解除隐藏约束，二者只表达菜单栏协作，不作为退出 Launcher 模式、解除绑定或停止业务的信号。接入文档需说明应用将 Launcher 的约束叠加在自身设置之上。界面应区分用户许可、请求应用结果和应用是否自行显示；主动允许应用保留入口属于正常状态，不能显示成接管失败。

沿用入口归还契约：Launcher 退出、连接结束或解除绑定后，应用恢复自身控制，已有运行实例继续运行；重连后重新应用保存的许可。SDK 的菜单栏回调串行执行，断连归还排在在途回调之后，避免迟到隐藏覆盖归还。Launcher 正常退出时先尽力归还入口并关闭 SDK 服务端，原生层等待有界，超时后仍由 SDK 断连归还兜底。

验收覆盖四种许可与应用设置的组合、两个项目互不影响、离线保存与重连、重启后许可保留、拒绝与超时重试、能力不支持、解除绑定后重新关联，以及快速切换与旧会话迟到确认不能覆盖最新选择。通用检查经项目检查脚本运行，实际菜单栏显隐和退出/失联归还另做 Mac 原生联调；未执行的联调必须明确报告。

2026-10-07 验证：格式检查通过，静态分析零诊断，297 项核心/SDK 测试和 49 项 widget 测试通过，Mac debug 构建通过。临时 AppKit 应用的真实 `NSStatusItem` 验证了四种许可组合及连接结束后的归还；使用临时 HOME 启动本次构建的 Launcher，验证默认隐藏、正常退出恢复应用自身显示/隐藏设置，并检查管理窗口截图。具体 VPN 项目尚未提供，接入方仍需实现上述回调契约。
