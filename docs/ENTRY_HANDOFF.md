# 入口接管与归还

被管理应用配合 Launcher 暂时收起自己的菜单栏入口，或按自身设置保留入口。
整个过程由应用显式确认，实际入口和网速等内容仍由应用提供。

## 接管流程

1. 应用通过 SDK 连接并完成注册。
2. 启动器先完成一次状态查询（确认会话可用），再向应用发送
   `setEntryManaged(managed: !菜单栏显示许可)`。
3. 应用自行判断后确认；启动器只有在收到确认且会话和用户选择仍是当前值时
   才标记「接管完成」（要求隐藏）或「菜单栏：由应用决定」（已允许）。
   许可开启不能作为入口实际可见的证据。拒绝、超时或状态查询失败时显示
   「尚未应用」，保留选择供用户重试，下次连接时再次应用。
4. 应用未声明 `setEntryManaged` 能力时，启动器不发送请求，界面显示
   「应用保留自身入口」，开关置灰并注明「应用不支持菜单栏控制」，其余服务
   协作照常。

## 菜单栏显示许可

每个项目卡片提供「允许应用显示菜单栏」开关，按项目标识保存到 Launcher
本地，配置绑定与运行时绑定共用规则，默认关闭。在线修改立即请求应用，
离线修改保存后在下次连接时应用。改名或迁移原绑定保留许可；解除绑定清除
许可，重新关联后默认关闭。菜单栏许可不影响 SDK 连接和服务管理。

- 许可关闭：应用暂时隐藏菜单栏入口，不改应用自身的显示设置。
- 许可开启：解除 Launcher 隐藏约束，应用自身仍可选择不显示。
- 应用自身的显示设置变化时，也按「应用自身允许显示 && Launcher 未要求隐藏」
  更新入口，不把 Launcher 的约束写入应用自身偏好。

## 归还与兜底

- 连接结束、错误或心跳超时（SDK 每 5 秒 ping，超过 15 秒未回 pong 即断开），
  SDK 对已请求隐藏的入口调用 `onSetEntryManaged(false)`，包含隐藏请求未确认
  的情形。回调按顺序执行，迟到的隐藏先完成再归还；应用恢复自身控制，是否
  显示仍由自身设置决定。通信关闭不等待应用菜单栏回调，回调应及时完成。
- 旧连接或旧选择的迟到确认永远不会覆盖新状态；每项目请求串行执行，SDK
  也串行执行应用菜单栏回调。
- 解除绑定或正常退出路径会尽力向仍在线、支持菜单栏控制的会话发送
  `setEntryManaged(false)`（短超时，失败不阻塞），兜底仍是上面的心跳机制。
- 解除绑定还会**主动关闭该项目的 SDK 会话**（归还入口后关闭一次，移除
  绑定记录后再关闭一次，拦截关闭与移除之间挤进来的重连）；此后该
  `projectId` 的握手按未知项目处理：重新进入待批准（`pending-approval`，
  除非已加入忽略列表），直到用户再次批准或重新关联配置。
- 正常退出使用 macOS 延迟退出回调：并行归还入口后关闭 SDK 服务端；原生层
  最多等候 2 秒，超时退出后由应用 SDK 的断连归还兜底。
- 任何路径都不会为了归还入口而回收业务。

## 打开原窗口

应用声明 `openWindow` 能力时，项目卡片提供「打开窗口」按钮。未声明能力时按钮
不可用且不发送请求；超时按「结果未知」展示。
