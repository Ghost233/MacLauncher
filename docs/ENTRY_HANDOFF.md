# 入口接管与归还

被管理应用可以自愿把「管理入口」（如菜单栏图标）交给启动器代为展示。整个过程
由应用显式确认，连接结束时由应用自行归还。

## 接管流程

1. 应用通过 SDK 连接并完成注册。
2. 启动器先完成一次状态查询（确认会话可用），再向应用发送
   `setEntryManaged(true)`。
3. 应用自行判断后确认；启动器只有在收到确认且会话仍是当前会话时才标记
   「接管完成」。确认失败时应用保留自己的入口，允许短暂双入口。
4. 应用未声明 `setEntryManaged` 能力时，启动器不发送请求，界面显示
   「应用保留自身入口」，其余服务协作照常。

## 归还与兜底

- 连接结束、错误或心跳超时（SDK 每 5 秒 ping，超过 15 秒未回 pong 即断开），
  由应用侧 SDK 自行归还入口——启动器崩溃不会留下无主入口。
- 旧连接的迟到确认永远不会标记新会话（按启动器会话标识对账）。
- 解除绑定或正常退出路径会尽力向仍在线的受管会话发送
  `setEntryManaged(false)`（短超时，失败不阻塞），兜底仍是上面的心跳机制。
- 解除绑定还会**主动关闭该项目的 SDK 会话**（归还入口后关闭一次，移除
  绑定记录后再关闭一次，拦截关闭与移除之间挤进来的重连）；此后该
  `projectId` 的握手一律按「未关联」拒绝，直到用户重新关联项目。
- 任何路径都不会为了归还入口而回收业务。

## 打开原窗口

应用声明 `openWindow` 能力时，项目卡片提供「打开窗口」按钮。未声明能力时按钮
不可用且不发送请求；超时按「结果未知」展示。
